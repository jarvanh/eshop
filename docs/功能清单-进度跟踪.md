## 0. 使用说明

### 0.1 字段定义

| 字段 | 说明 |
|---|---|
| **重要性** | `P0` MVP 必须（不做无法上线运营）· `P1` 完整体验（上线后快速跟进）· `P2` 规模化（商业化阶段） |
| **实现方式** | `芋道` 底座直用 · `yshop移植` 从 yshop-drink 开源版移植（MIT 已核验）· `自研` · `三方SDK` · 组合标注 |
| **参考项目** | 可参考的开源项目；标注（只读）= 协议不允许拷代码，仅设计参考；未标注 = MIT 可拷（保留版权声明并入 NOTICE.md） |
| **阶段** | 里程碑编号 + 分期，如 `M2·P0`；与计划 §5 对应 |
| **复杂度** | `S` 简单（CRUD/页面级）· `M` 常规（单域功能）· `L` 复杂（跨域/状态机/并发）· `XL` 子系统级 |
| **状态** | `未开始` → `进行中` → `已完成` → `已验收`（里程碑验收通过才算已验收） |
| **完成时间** | 填实际完成日期 `YYYY-MM-DD`；已验收填验收日 |
| **负责人** | 按计划 §9 角色（后端A / 后端B / Web前端 / 小程序）或真实姓名 |
| **备注** | 依赖关系、验收要点、优先级调整记录 |

### 0.2 维护规则

1. **更新时点**：每周例会过一遍 `进行中` 项；里程碑结束批量对账
2. **状态只能前进**：返工不改回状态，在备注记 `YYYY-MM-DD 返工：原因`
3. **新增功能**：追加行（ID 顺延），不删除历史行；砍掉的功能标状态 `已取消` + 备注
4. **优先级变更**：需在例会确认，同步修订计划文档 §2，并在备注记录调整原因（本文件已有两处对计划 v2.0 的上调，见 A-08 / A-44 / C-30）
5. **完成时间不预填**：这是实际记录字段，不是排期字段——排期看阶段列 + 计划 §9 并行图
