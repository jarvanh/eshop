## 1. 核验方法

2. 无 LICENSE 文件的仓库，通过 GitHub / Gitee API 的 license 字段与 README 授权声明交叉核验；
3. 本地源码（yshop-drink 三端）直接检查仓库根 LICENSE 与 README「开源协议」章节；
4. 核验日同时确认：芋道 `master-jdk25` 分支真实存在（`git ls-remote` 见 `master / master-jdk17 / master-jdk25` 三分支）。

## 4. 结论与红线

### 4.1 主链路全绿 ✅

**底座（ruoyi-vue-pro）+ 主要移植源（yshop-drink 三端）+ 三个设计参考（BiteGo/TKOB/TastyIgniter）全部为 MIT**。计划中的代码移植策略（M1/M2/M4 从 yshop-drink 移植）法律上无障碍。

### 4.2 三条只读红线 ❌

| 项目                             | 协议                            | 风险                                                            |
| ------------------------------ | ----------------------------- | ------------------------------------------------------------- |
| fuint 系（fuint / fuintCatering） | AGPL-3.0 / 无 LICENSE + 商用收费声明 | AGPL 网络服务条款会传染整个 SaaS；「商用购买授权」声明意味着拷代码有直接侵权风险。**只看设计，不进一行代码** |
| Jeepay                         | LGPL-3.0                      | 库级传染：动态链接可用但修改其源码必须开源；对闭源 SaaS 仍建议只读                          |
| Floreant POS                   | MRPL 1.2                      | 弱著佐权 + 署名条款，修改后需开源。只读                                         |

### 4.3 mysql-connector-j 注意事项 ⚠️

GPLv2 + Universal FOSS Exception。**SaaS 服务端使用不触发分发义务，当前架构无风险**；但若未来做「私有化部署交付」（把软件打包卖给商家自建），需改用 MariaDB 驱动或评估 FOSS 例外适用性。已列入技术决策注意项。

### 4.4 相比原计划的两处修订

1. **BiteGo 升级**：原按「未知协议（毕设）只读」处理，现核验为 MIT，理论上可移植代码；但其技术栈为 NestJS/TS + MongoDB，无法直接移植到 Java，**实际用法不变（精读实现文档），法律状态从灰色变绿色**。
2. **fuint 定案**：原计划 M0 待核验，现结论为「无 LICENSE + AGPL 主仓 + 商用收费声明」→ 维持并强化只读红线，M0 该项核验任务**已完成**。
