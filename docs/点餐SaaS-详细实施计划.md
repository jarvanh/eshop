## 1. 项目概述

### 1.1 商业模式与前提假设

| 项    | 假设                                            | 变更影响                           |
| ---- | --------------------------------------------- | ------------------------------ |
| 商业模式 | 多租户 SaaS，卖给商家，平台收订阅费                          | 若自用则可砍掉 SaaS 计费                |
| 技术栈  | Java 25 + Spring Boot 4.1（芋道 master-jdk25 分支） | 详见 5.1 决策门与 ADR-D3             |
| 团队   | 4 人：后端 ×2、Web 前端 ×1、小程序 ×1                    | ⚠️ 清单为"终态产品"范围，必须按优先级分期（见 5.0） |
| 部署   | Docker Compose 起步，单体模块化                       | 后期可按模块拆微服务                     |
| 资金合规 | 支付走商家自有商户号（普通商户模式），平台不经手订单资金                  | 规避二清；商家/骑手提现属代发场景，见 6.5        |

### 1.2 功能范围（来自 xlsx，三端结构）

xlsx 清单比最初需求表大幅扩展，确认产品终态为**五端一云**：

| 端     | 形态                      | 核心内容                                                                                 |
| ----- | ----------------------- | ------------------------------------------------------------------------------------ |
| 后台管理端 | Web（平台运营用）              | 装修、工作台、收银台、桌台、门店、商品、订单（堂食/外卖/自取/预约/收银五类）、会员、骑手、营销、统计、财务、支付、快递、消息、微信管理、基础设施、系统管理、租户管理 |
| 门店端   | Web（门店员工用，同后台不同角色/数据权限） | 工作台、收银台、门店中心（桌号/打印机/广告/收支/提现/桌面分类/预约标签/规则）、商品中心、订单中心、营销中心                            |
| 顾客移动端 | uniapp（小程序/H5）          | 首页、点餐、购物车、订单（含扫码继续加餐）、支付、优惠券、用户中心、积分商城、门店、提前预约                                       |
| 商家中心  | uniapp 内商家角色页           | 数据面板、桌台协助点餐、菜品管理、订单实时+出单打印、商家提现、我的管理                                                 |
| 骑手中心  | uniapp 内骑手角色页           | 首页数据、接单大厅、收入明细、历史订单、提现                                                               |

### 1.3 关键决策记录（ADR）

| #  | 决策                                            | 理由                                                                                                                             |
| -- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| D1 | 底座用 ruoyi-vue-pro（单体完整版，master-jdk25）         | system/infra/pay/member/mall/mp/promotion/trade 覆盖基础能力 60%+；MIT；社区最大。yshop 本身即芋道同源 fork（表结构 system\_*/infra\_* 同构），业务模块移植对齐成本低 |
| D2 | 不用 yudao-cloud 微服务版                           | 4 人团队养不起 Nacos/Gateway/Seata 全家桶                                                                                               |
| D3 | master-jdk25（JDK25 + SB4.1）起步                 | SB 3.5 OSS 支持 2026-06-30 已结束；day-0 升级最便宜；上游已正式适配。M0 设半天决策门，红灯退 master-jdk17                                                    |
| D4 | 多人协同点餐自研（服务端权威）                               | 无任何开源实现可抄（见 D6 实证）；产品差异化护城河                                                                                                    |
| D5 | 支付走普通商户模式                                     | 平台不经手订单资金，规避二清                                                                                                                 |
| D6 | **yshop-drink 开源版只作部分移植源，缺口全部自研**（详见 §4.2 实证） | 上游完整开源版经源码核验为 open-core：骑手/提现/会员卡购买/预约/桌台/收银挂单/打印机管理等均为商业版功能，开源仓库无实现                                                           |
| D7 | **不购买 yshop 商业版授权，分期自研缺口**                    | 商业版为 SB3/JDK17 技术栈，迁移到芋道 jdk25 底座仍需大量适配；且长期演进绑定其架构。改为 P0/P1/P2 分期（§5.0）控制节奏。**若团队后续评估工期不可接受，此决策可复议（买断价 vs 4 人月成本对比）**          |
| D8 | 门店端不单独开发第二套管理端                                | 同一 Vue 后台 + 角色菜单/数据权限（门店角色仅见本店），芋道 RBAC 原生支持                                                                                   |
| D9 | 外卖配送双轨制：初期第三方同城配送（UU 跑腿等），骑手自配送放 P2           | 骑手体系（入驻/调度/提现/骑手端）是完整子系统，MVP 不应被它阻塞                                                                                            |

### 2.4 覆盖率结论

- **芋道底座直供**：约 45 项（系统/基础设施/微信/支付/会员/订单骨架）

- **yshop 开源可移植**：约 15 项（商品规格三表、券、积分商城、快递、素材、广告、服务菜单、门店基础）

- **必须自研**：约 35 项（桌台体系、协同、收银挂单、打印、预约、骑手、提现、财务、会员卡购买、工作台、统计）

- 三方 SDK：快递100、UU跑腿、易联云/飞鹅、高德/腾讯定位、微信全家桶

## 3. 总体架构

### 3.1 分层架构（五端一云）

```
┌──────────────────────────────────────────────────────────────────┐
│ 接入层（五端）                                                     │
│  后台管理端 Vue3 ─┐                                               │
│  门店端 Vue3 ──────┼─ 同一前端工程 · 角色菜单+数据权限（D8）          │
│                   │                                               │
│  顾客 uniapp ──────┤ 小程序/H5                                     │
│  商家中心 uniapp ──┤ 同一 uniapp · 商家角色页                       │
│  骑手中心 uniapp ──┘ 同一 uniapp · 骑手角色页（P2）                  │
├──────────────────────────────────────────────────────────────────┤
│ 应用层（单体 yudao-server，1 个 JAR）                               │
│  ┌── 自研核心 ──────────────────────────────────────────────┐     │
│  │ yudao-module-store  门店/桌台/桌台会话(协同)/预约           │     │
│  │ yudao-module-pos    收银台/挂单取单/聚合支付B扫C/云打印      │     │
│  │ yudao-module-delivery 骑手/接单大厅/三方同城配送适配 (P2)    │     │
│  │ yudao-module-finance 收支明细/提现/提现账户 (P2)            │     │
│  │ yudao-module-saas   套餐计费/配额/租户开通                  │     │
│  └──────────────────────────────────────────────────────────┘     │
│  ┌── 芋道底座（裁剪保留）───────────────────────────────────┐     │
│  │ system 多租户/RBAC · infra 代码生成/文件/OSS/监控           │     │
│  │ product 商品SKU · promotion 券/装修 · trade 订单            │     │
│  │ member 会员/积分/地址 · pay 支付/钱包 · mp 公众号全套        │     │
│  └──────────────────────────────────────────────────────────┘     │
├──────────────────────────────────────────────────────────────────┤
│ 基础设施层                                                          │
│  MySQL 8 · Redis 7 · RocketMQ 5（打印/订单事件/对账）· OSS+CDN      │
├──────────────────────────────────────────────────────────────────┤
│ 外部服务                                                            │
│  微信生态（支付/小程序/公众号/开放平台第三方）· 易联云/飞鹅云打印      │
│  快递100 · UU跑腿 · 高德/腾讯定位 · 短信                            │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 技术栈（定稿）

| 层             | 选型                                                     |
| ------------- | ------------------------------------------------------ |
| 后端            | JDK 25 (LTS) + Spring Boot 4.1（芋道 master-jdk25）        |
| ORM / 缓存 / 消息 | MyBatis Plus 3.5.16+ / Redis 7 + Redisson / RocketMQ 5 |
| 实时通信          | WebSocket（协同购物车、工作台、商家订单推送）；多实例 Redis Pub/Sub          |
| 管理端           | yudao-ui-admin-vue3（后台+门店端同工程多角色）                      |
| 移动端           | uniapp 单工程多角色（顾客/商家/骑手）                                |
| 文档            | Knife4j boot4 starter 5.0.x                            |
| 部署            | Docker Compose（Nginx + app + MySQL + Redis + RocketMQ） |

### 3.3 部署形态

- 开发：本地 docker-compose 起中间件，yudao-server IDEA 直跑

- 生产：Nginx + app（水平扩容，会话在 Redis）+ MySQL 主从 + Redis 哨兵 + RocketMQ

- 扩容路径：单体多实例 → 协同 WS / 订单热点拆独立服务 → 必要时全面微服务化

**开源版实际包含**（建表清单为证）：

- system / infra 全套（芋道同源）

- mp 公众号全套（账号/自动回复/素材/菜单/标签/粉丝）

- 商品三表规格模型（storeproductattr / attrresult / attrvalue）+ 品牌/分类/评价/运费模板

- 订单（storeorder / cart\_info / status）+ 订单号

- 优惠券（coupon / couponuser）

- 积分商城（scoreproduct / scoreorder，含运费模板三表）

- 快递（express）、素材库（material/group）、广告（shopads）、服务菜单（service）

- 门店（storeshop）、会员（user / user\_address / user\_bill）、微信模板

**开源版没有**（xlsx 清单里的以下功能在开源仓库零实现，属商业版）：

- 骑手全套（rider/courier 关键词命中 0）

- 收银台（cashier 命中 0）、挂单/取单（命中 0）

- 桌台管理/桌台会话（reserve/table 无业务实体，仅 codegen 演示）

- 打印机管理（仅 PrintToken/PrintMechin 两个 Redis DAO 残迹）

- 预约体系（标签/规则）、会员卡购买、提现（仅一个枚举残迹）

- 工作台、商家中心移动端、骑手中心、门店端控制台

- uniapp 开源版仅 4 个页面目录（index/menu/mine/order）

> 结论：**xlsx ≈ yshop-drink 商业版功能矩阵；开源版约覆盖 1/3**。此实证是 D6/D7 决策的依据。

### 4.3 移植与合规纪律

- 可拷代码：仅 MIT 项目（芋道、yshop、BiteGo、TKOB、TastyIgniter、FlashWaimai），保留版权声明 + `NOTICE.md` 登记

- 严格只读：fuint 系、Jeepay、Floreant

- CI：license-maven-plugin（后端）+ license-checker（前端）扫描；GPL/AGPL/LGPL 无例外项直接失败

- mysql-connector-j（GPLv2+FOSS Exception）：SaaS 服务端无风险；私有化交付场景换 MariaDB 驱动

## 6. 关键技术方案

### 6.1 多人协同点餐（服务端权威）

```jsonc
// 客户端意图
{ "action": "add_item", "skuId": 1001, "qty": 2,
  "opId": "uuid", "sessionId": "S123", "version": 42 }
// 服务端广播
{ "type": "cart_snapshot", "version": 43,
  "items": [...], "members": [...] }
// 409 冲突 → 拉全量快照 → 重放未提交操作
```

服务端唯一事实源；`cart.version` 乐观锁 + `opId` 幂等（5min 窗口）；多实例 Redis Pub/Sub 广播；会话生命周期与订单域事件解耦。

### 6.2 优惠计算管道 + 快照

会员价→券→积分→储值，管道式计算；优惠快照（用什么/抵多少/行级分摊）整体序列化入订单；规则修改不影响历史与退款。

### 6.3 挂单/取单与云打印

- 挂单：pos\_order 状态 `parked` + 挂单区队列；取单恢复编辑；超时提醒（工作台红点）

- 打印：下单→RocketMQ→打印消费者→print\_task 状态机→指数退避×5→人工补打；后厨分单按分类路由、故障降级备用机

### 6.4 配送调度抽象（D9 双轨）

```
DeliveryDispatcher 接口
 ├── ThirdPartyAdapter   UU跑腿/达达/蜂鸟（下单/取消/状态回调/运费查询）
 └── SelfRiderService    自有骑手（呼叫/抢单/派单/状态流）（P2）
```

外卖单创建时按门店配置路由配送渠道；状态回调统一归一到订单配送状态机。

### 6.5 提现与资金合规

- 订单资金：普通商户模式直接进商家账户（平台不碰）——无二清

- 商家/骑手提现：属平台代发场景（平台营销补贴、骑手佣金），走**微信商家转账 API**（需另立主体与合同），提现申请-审核-打款-对账四步留痕

- 储值预付卡：属地单用途预付卡规定调研后决定开通范围

### 6.6 库存与对账

Redis Lua 预扣 → DB 乐观锁兜底 → 超时回滚；每日拉微信/支付宝账单 ↔ 本地流水逐笔核对，差异人工队列。
